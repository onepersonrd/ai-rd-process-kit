# AI R&D Process Kit（日本語）

**AIコーディングエージェントに「勝手に範囲を広げる」「試していないのに完了と言う」「確認せずに断定する」「同じ失敗を繰り返す」をさせないための、3つの文書と1つの習慣。**

ハードウェア（基板・ファームウェア）とソフトウェアを、AIエージェントに大半を書かせて開発している一人R&Dの実運用から、製品固有の部分を外して一般化したものです。Claude Code 用のスキルを同梱していますが、雛型とルールは Markdown を読めるどのエージェントでも使えます。

## 考え方

実装の前に、エージェントに3つの文書を書かせ、人が承諾してから着手します。

1. **計画**（`plan.md`）: 範囲を7項目で絞る（制約、ビジョン、初回リリース、コアコンセプト1文、作らないこと、MVP、拡張の道筋）。完了条件をタスクより先に書く。進捗%は 0／25／50／75／100 の意味を固定し、**100は「レビューで承諾、かつテスト合格」だけ**。
2. **設計書**（`design-doc.md`）: 章を最初に全部作る。該当しない章は「該当なし（理由）」と書く。却下した案も理由つきで残す。設計の順序は「データ→機能→画面」。
3. **要求↔テスト対応表**（`requirements-test-matrix.md`）: 要求の全項目にテストを1つ以上。合格基準は数値。「未実施」を「合格」と書かない。

作業中は小さく区切って確認を受け、設計を変えたらその作業の中で設計書を更新します。失敗したら、エージェント自身が**教訓ログ**（`lessons-learned.md`）に「状況・原因・再発防止」を書き、次のセッションの最初に読みます。

## 中身

- `templates/` — 計画、設計書、要求↔テスト対応表、教訓ログ（実例4件つき）
- `rules/CLAUDE.md.example` — プロジェクトの根に置く「約束」13項目
- `skills/rd-process/SKILL.md` — Claude Code 用スキル（セッション開始、文書作成、作業、テスト、記録、セッション終了）

## 使い方（5分）

1. `templates/*.md` をプロジェクトの `docs/` にコピーする。
2. `rules/CLAUDE.md.example` をプロジェクトの根に `CLAUDE.md` として置き、[ ] の部分を書き換える。
3. Claude Code なら `skills/rd-process/` を `.claude/skills/` にコピーする。他のエージェントは `SKILL.md` の中身を指示に貼る。
4. 作りたいものを伝える。エージェントが**コードを書く前に**範囲の表を出して承諾を求めてくれば、ルールが効いています。

## 出典と開示

雛型は、小さなハードウェア製品（基板、ファームウェア、PCツール）を Claude Code で開発している一人R&Dの運用ルールを一般化したものです。教訓の実例は実際の記録から製品名を除いたものです。この文書は AI の下書きを著者が実体験で書き直しました。

有料の補足パック（記入済みの実例、AIの失敗の型と検査リスト、ネットリストと部品入手性の検査、日本語の運用解説）を予定しています。無料版はこのまま無料です。
